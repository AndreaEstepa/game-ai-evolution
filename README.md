# Silksong: perception and evolutionary learning

This workspace contains the basis of a project for an AI agent to play a delimited section of the *Hollow Knight: Silksong* map. The idea is to connect the visual perception of the game with a neural policy trained using an EDNN evolutionary algorithm.

> **Current status:** Screen capture and template-based detection of Hornet and flowers are implemented. The ROS 2 publisher exposes both an image mask and structured detections. An initial fixed-topology MLP with a genetic algorithm consumes those detections and publishes abstract actions. Fitness is entered manually per episode; game controls, automatic episode resets and automatic fitness measurement are not implemented.

## Objective and planned architecture

The objective is to train and evaluate an agent in a specific section of the map, starting with a limited route or task. The expected flow is:

```text
game screen
↓
Visual capture and preprocessing (implemented)
↓
Observation for the agent
↓
MLP policy + genetic algorithm (baseline implemented)
↓
Abstract action topic (implemented)
↓
Game control adapter (pending)
↓
Episode score (manual for now)
└──────────────→ next generation
```

Each individual represents the weights of a candidate fixed-topology neural policy. The baseline uses tournament selection, elitism, uniform crossover and Gaussian mutation. The observation uses Hornet's position/orientation and the nearest flower's relative position/confidence. Fitness is currently supplied manually; the task-specific formula and automated episode evaluation remain to be defined. Detection uses image templates and should not be treated as general-purpose semantic vision.

## What exists today

The ROS 2 package `silksong_capture` captures a region of a monitor and processes it with OpenCV. It publishes a monochrome image to `/vision/red_mask` (`sensor_msgs/msg/Image`) and JSON detections to `/vision/detections` (`std_msgs/msg/String`). The JSON contains Hornet's position, orientation and confidence, plus flower positions and confidence scores.

The `scripts/` scripts test capture and visualize processing without ROS 2. The `evolutionary_agent` node subscribes to `/vision/detections` and publishes abstract button choices to `/agent/action`; `/agent/start_episode` starts an evaluation and `/agent/fitness` supplies its score. It does not send game inputs or determine episode fitness automatically.

## Capture Settings

The parameters are in [config.json](config.json) and in [src/silksong_capture/config/config.json](src/silksong_capture/config/config.json). The scripts read the first and the ROS 2 package loads the second; You have to keep them synchronized when the values are changed.

| Key | Usage |
|---|---|
| `monitor` | Index of the monitor being captured. |
| `region` | Captured rectangle (`left`, `top`, `width`, `height`), relative to the monitor. |
| `window_name` | Window title used by test scripts. |
| `fps_limit` | Target capture/publish frequency. |
| `vision.resize_width`, `vision.resize_height` | Processing and publication resolution. |
| `vision.blur`, `vision.threshold`, `vision.adaptive_threshold` | Noise reduction and thresholding parameters. |
| `vision.canny_low`, `vision.canny_high`, `vision.min_area` | Contour detection and filtering parameters. |
| `vision.red_detection.enabled` | Enable red detection in test scripts. |
| `vision.red_detection.saturation_min`, `vision.red_detection.value_min` | HSV thresholds for the red mask. |

The position of the region depends on the resolution, monitor layout and game window. It must be adjusted to the environment where it is executed.

## Requirements

- Python 3.
- ROS 2 and `colcon` to compile and run the nodes.
- Package ROS dependencies: `rclpy`, `sensor_msgs`, `std_msgs` and `ament_index_python`.
- Python libraries used by the code: `mss`, `numpy` and `opencv-python` (`cv2`).

The image publisher uses `cv_bridge` to convert the OpenCV mask into a ROS image message. The installation of ROS 2 and its dependencies varies by distribution and operating system. On Windows, install a native ROS 2 distribution and the Python libraries in the same environment used to run the nodes; Windows end-to-end execution has not yet been verified. See the [official ROS 2 Windows installation guide](https://docs.ros.org/en/jazzy/Installation/Windows-Install-Binary.html).

## Run the visual tests

From the root of `silksong_ws`, with Python dependencies available:

```bash
python3 scripts/capture_test.py
python3 scripts/processor_test.py
```

`capture_test.py` shows the captured region. `processor_test.py` displays windows for the original image, the binary image, the edges, the grayscale, and, if enabled, the red mask combined with the edges. Press `q` to close the windows.

## Compile and run the ROS 2 publisher

On a terminal with the ROS 2 environment installed and configured:

```bash
cd silksong_ws
source /opt/ros/<distro>/setup.bash
colcon build --packages-select silksong_capture
source install/setup.bash
ros2 run silksong_capture screen_publisher
```

Replace `<distro>` with the installed ROS 2 distribution. The node publishes to:

```text
/vision/red_mask
/vision/detections
```

Run the policy in another terminal with the same ROS environment:

```bash
ros2 run silksong_capture evolutionary_agent
```

The policy's action/evaluation topics are `/agent/action`, `/agent/start_episode`
and `/agent/fitness`. See the workspace README for the manual evaluation loop.

To check the topics from another terminal with ROS 2 configured:

```bash
ros2 topic list
ros2 run rqt_image_view rqt_image_view
```

In `rqt_image_view`, select `/vision/red_mask`.
